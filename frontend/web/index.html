      How it works

      Four steps, all triggered by things you already do on GitHub.

      1. 01

        Tag the issue

        Add a bounty label with an amount. Funds move into escrow immediately — no separate invoice or approval chain.

      2. 02

        Escrow holds it

        A chain-agnostic contract locks the funds in ERC-20 stablecoins until the work is verified as done.

      3. 03

        Contributor merges

        Anyone can pick up the issue, open a PR against it, and get it reviewed and merged as usual.

      4. 04

        Wallet gets paid

        The merge event fires a webhook that releases the escrow straight to the contributor's wallet — same day.

      Under the hood

      Built on well-documented, boring-on-purpose tooling — Next.js, GitHub webhooks, and a four-function Solidity contract.

      Client
      bounty board, wallet UI       → Event engine
      verifies GitHub webhooks       → Escrow contract
      holds and releases funds

      Verified webhooks

      Every webhook is HMAC-signed per repository, so forged or replayed events are rejected before they ever touch escrow.

      Timelocked refunds

      If a bounty goes stale, a configurable timelock returns the funds to the maintainer automatically. Nothing gets stuck.
